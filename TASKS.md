# Задачи проекта

Обновлено: 2026-11-16. Подготовка интеграционной ветки `release/0.5.0-alpha.2`.
Контекст и история проверок: [WORK_NOTES.md](WORK_NOTES.md).
Checkpoint для возобновления сессии: [SESSION_HANDOFF.md](SESSION_HANDOFF.md).

## Правила выполнения

- Сохранять существующие изменения; не откатывать рабочее дерево и подмодули.
- Работать самостоятельно; Flint не вызывать.
- Проверки и сборки проводить локально. CI — финальная проверка перед релизом.
- Разбивать только собственный код проекта. Чужие крупные файлы из upstream,
  vendored-код и generated-файлы не декомпозировать; сначала проверять происхождение.
- Большие исходники разбивать по ответственности, а не на произвольные куски.
  Имена файлов должны отражать домен. Не сохранять старые копии перенесённого кода.
- Общую логику держать в одном месте; различия платформ оформлять адаптерами.
- Сохранять API/IPC, wire-format, cfg, события, порядок сообщений,
  транзакционные границы, ratchet commit, X3DH, ACK и replay-защиту.
- Рефакторинг и исправления поведения выполнять отдельными проверяемыми шагами.
- Не менять длину I2P-туннелей ради ускорения измерений.
- Владелец разрешил коммиты, push, GitHub Actions и релиз alpha2.
- Перед новыми сборками объединить все ветки; затем проверять общий commit SHA.
