# Короткие контактные карточки v3

Состояние на 28 октября 2026: неопубликованная реализация в ветке
`feat/today-integration-20261028`. Новые карточки имеют вид
`gipny:v3:<payload>`: только ASCII-буквы, цифры, `:`, `-` и `_`, без пробелов,
переносов строк, percent encoding и `=` padding. Их можно копировать одной
строкой или сканировать как QR. Старые корректные v1/v2 продолжают читаться.

Без имени карточка с адресом релея содержит **187 символов**. Карточка без
релея — 144; сама по себе она не сообщает, куда доставлять почту, и не годится
для подключения агента. Имя необязательно и увеличивает длину; максимум —
96 байт UTF-8 и 316 ASCII-символов всей карточки. Длинное имя не обрезается:
экспорт возвращает ошибку. UI должен показывать ошибку и не копировать её
текст как карточку.

## Что осталось целым

Карточка сохраняет оба публичных ключа полностью: Ed25519 32 байта и X25519
32 байта. Отпечаток личности вычисляется по тем же ключам; ключи не
усекаются и не заменяются коротким идентификатором.

Вместо полного I2P Destination сохраняются его 32 байта SHA256. Если адрес
уже `.b32.i2p`, декодируется тот же полный 256-битный хеш. Сохраняются оба
адреса: исходящий адрес владельца и, если есть, адрес релея. После чтения
они возвращаются в канонической lowercase `.b32.i2p` форме.

Это обычная адресация I2P, без внешнего сервиса сокращения ссылок. При этом
карточка больше не несёт полный сертификат Destination: получение полного
адреса при соединении требует штатного I2P lookup/LeaseSet. Доставка уже
использует релей получателя; исходящий адрес остаётся отдельным полем.
Сетевая доступность адреса и успешный lookup проверяются отдельно.
[I2P naming specification](https://www.i2p.net/en/docs/overview/naming/).

Четырёхбайтовая checksum обнаруживает ошибки копирования. Она **не подпись**
и не доказывает, кому принадлежит карточка. Атакующий может создать свою
корректную карточку; доверие к личности по-прежнему требует сверки отпечатка.

## Канонический формат

Prefix — строго `gipny:v3:`. Payload — Base64URL без padding.

| Поле | Размер | Порядок |
|---|---:|---|
| flags | 1 | bit0: релей присутствует; bit1: имя присутствует; прочие биты запрещены |
| sign_pk | 32 | Полный Ed25519 public key |
| dh_pk | 32 | Полный X25519 public key |
| outbound hash | 32 | SHA256 сериализованного Destination |
| relay hash | 0 или 32 | При установленном bit0 |
| name length | 0 или 1 | При bit1, длина имени в байтах, 1–96 |
| name | 0–96 | Строгий UTF-8, без нормализации/усечения |
| checksum | 4 | Первые четыре байта SHA256(domain || предшествующие байты) |

Domain — ASCII `gipny/contact-card/v3` и завершающий нулевой байт. Версия
тем самым участвует в checksum. Пустое имя кодируется отсутствием поля.
Unknown flags, неполные/лишние байты, некорректный UTF-8, padding и ненулевые
хвостовые биты Base64URL отклоняются. Декодер ограничивает размер до выделения
буфера. Whitespace допускается только снаружи всей карточки для вставки.

Полные I2P-адреса на экспорт ограничены 4096 ASCII-символами. Проверяются
алфавит, padding, хвостовые биты и framing Destination: 387 байт плюс точная
длина сертификата из байтов 385–386. Проверка реальных алгоритмов сертификата
и соединения остаётся libi2pd.
[I2P common structures](https://www.i2p.net/en/docs/specs/common-structures/).

## Реализация и проверки

Rust-кодек находится в `libcore/src/card.rs`; UI — в `ui/src/contact-card.ts`,
публичные импорты из `ui/src/api.ts` сохранены. UI использует pinned
`@noble/hashes` 2.4.0 и синхронный `sha256` из `sha2.js`, Rust — существующий
`sha2`; собственного криптографического хеша здесь нет.
[API и исходники noble-hashes](https://github.com/paulmillr/noble-hashes),
[релиз 2.4.0](https://github.com/paulmillr/noble-hashes/releases/tag/2.4.0).

Общие golden vectors — `tests/fixtures/contact-cards-v3.json`. Они включают
оба адреса, отсутствие релея, Unicode/границу длины имени, uppercase b32,
full Destination с null/key certificate и некорректные карточки с правильной
checksum, но запрещёнными flags, длиной или UTF-8. Их независимо создаёт и
проверяет Python stdlib (`hashlib`/`base64`):

```sh
python3 scripts/check-contact-card-fixtures.py
```

Эта data-only проверка выполнена: 8 положительных и 13 отрицательных
примеров, размеры 187/144/316 подтверждены. Она не выполняет Rust/TS-код.
Компиляция и исполнение тестов Rust/UI разрешены только в GitHub CI.
На 2026-10-28 для SHA `38892f6` подтверждены frontend build и 17/17 UI-тестов,
включая общие vectors, legacy import и запрет копирования ошибки экспорта:
[GitHub job](https://github.com/gluckdev/gipny-i2p/actions/runs/40759359493/job/123066773196).
Проверки установщиков Unix/Windows также
[прошли](https://github.com/gluckdev/gipny-i2p/actions/runs/40759359392).
Android Rust/JNI compile check со stub-роутером
[прошёл](https://github.com/gluckdev/gipny-i2p/actions/runs/40759359494/job/123067407448);
он не подтверждает рабочий транспорт. Native job с настоящим встроенным
роутером также [прошёл](https://github.com/gluckdev/gipny-i2p/actions/runs/40759359493/job/123066772990):
libcore 173/173, в том числе все 7 тестов карточек. Живое I2P-соединение через
карточку v3 требует отдельного результата CI, а не вывода из fixtures.
