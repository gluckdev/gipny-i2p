### Карточки и переписка

Улучшен поиск оставшихся копий почты после отключения прежних узлов DHT.
Клиент проверяет новых держателей и использует полученные адреса в текущем
опросе. Доставка по-прежнему зависит от доступности сети и сохранившихся копий.

Новые контактные карточки `gipny:v3` занимают 187 символов с адресом релея
без имени. Оба публичных ключа сохраняются полностью; адреса используют
стандартный I2P destination hash. Старые карточки v1/v2 читаются. Для приёма
v3 требуется эта или более новая версия; checksum обнаруживает ошибки
копирования, а личность подтверждается сверкой отпечатка.

Удаление личного сообщения создаёт устойчивую запись удаления и повторяется
до аутентифицированного подтверждения собеседника. У совместимых клиентов
удаляются текст и вложения; нумерация сохраняет пропуски. Очистка диалога и
таймер используют тот же механизм. Уже сохранённые внешние копии этим не
отзываются. Групповая доставка сохраняет очередь до E2E ACK каждого получателя.

### Хранилище и память

Новый формат профиля требует OS credential provider в дополнение к паролю.
Копирование каталога на другое устройство не переносит доступ. Старые
переносимые `.device`/vault и plaintext базы headless-агентов отвергаются
без удаления: рабочий путь переноса — явно зашифрованный export/import с новой
привязкой назначения. Android требует аппаратный TEE/StrongBox; Linux/OpenWrt
требует provisioned Secret Service, наличие готового бинарника недостаточно.

Idle Rust keys запечатываются с ограниченной locked NOACCESS-страницей;
известные native/FFI/backup buffers очищаются, WebView держит меньше открытых
копий. Полное шифрование всех C++/SQLCipher/renderer buffers и защита от
скомпрометированной ОС не заявляются. Подробности и пределы:
[device storage](../device-bound-storage.md), [RAM](../memory-security.md).

### Установка и интерфейс

Rustls обновлён до 0.23.46 с исправлениями опубликованных TLS advisories.
Контрольные суммы пакетов и provenance относятся к окончательному исходному SHA.

Обновления требуют точного asset и валидной SHA256. Windows-агент сохраняет
старый binary до подтверждения готовности новой версии и восстанавливает
его при раннем сбое; это не откат миграций БД. Android/macOS отдельно
показывают передачу файла системному установщику. Release не позволяет
включить debug logging; диагностический профиль предназначен для тестов.

Обновлены English/Russian интерфейс и документация, сайт проекта с русским
языком по умолчанию и переключением на English,
агентские cat names и запрос карточки владельца. Все пакеты собираются в
GitHub Actions из публичных исходников; manifest и source archive позволяют
проверить их происхождение. Применимость OpenWrt определяется CPU/ABI,
kernel и OS credentials, без обещания совместимости только по году устройства.
