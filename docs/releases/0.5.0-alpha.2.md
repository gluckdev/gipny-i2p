Проверочная alpha-версия. Нативные пакеты сохраняют полный журнал разработчика:
адреса релеев, идентификаторы, имена вложений и тайминги могут попадать в журнал.
Тела сообщений не журналируются. Alpha не устанавливается стабильным каналом
автообновления; пакеты доступны на странице релиза после завершения Actions.

### Изменения

- Объединены все ветки разработки, актуальный проверенный pin i2pd и обновления
  зависимостей. Собственные Core, Session, DB, UPnP и UI разделены по доменам;
  чужие исходники не декомпозировались.
- Удалены режимы «кофеин» и «кокаин»: закрепление чата, удержание экрана и
  переключение на укороченный путь без padding. Обычная отправка сохраняет
  выравнивание размера сообщений и штатную длину I2P-туннелей.
- Ограничены ресурсы релея и проверяются границы DHT-запросов.
- Обновлены экран выбора языка, клавиатура, разбиение браузерного клиента и
  проверки совместимости WebView; сайт яснее описывает ограничения веб-версии.
- Native prewarm после одного router bootstrap параллельно готовит клиент и
  личный relay. Владение задачами привязано к профилю и generation; отмена
  ожидает их завершения, а unlock повторно проверяет готовность Destination.
- Browser параллельно загружает UI, config и WASM Worker и заранее проверяет
  только публичный bootstrap cache. До unlock не запускаются router или
  private identity; проверки подписи и свежести cache сохранены. Собственный
  browser adapter теперь явно задаёт application tunnels 3/3 вместо
  унаследованных 2/2; чужие defaults и exploratory policy не изменены.
- Ошибки WASM определяются в реальном Worker и показывают исходную причину.
  Временные уведомления центрированы с учётом клавиатуры и safe areas;
  обычная карточка не блокирует ввод и кнопки, а переполненный длинный текст
  можно прокрутить. Это не заменяет настройку сетевого сервиса на хостинге.
- Убраны автоматический запрос исключения из энергосбережения Android и
  неиспользуемый Kotlin biometric bridge.
- Автоматическая рассылка релизных сообщений отключена: прежний sender
  рассчитывал на команды, которых в агенте нет.

### Ограничения проверки

Первый [native throughput sweep](https://github.com/gluckdev/gipny-i2p/actions/runs/43875210051)
на `b1b1795` доставил и побайтно проверил восемь файлов по 32 MiB с cap 1…8,
при 3 hops и padding. Run завершился **failure**: точки 1, 3 и 8 нарушили 60-секундный
echo deadline. В этой серии cap 4 дал 202497 B/s и p95 echo 14.608 с, cap 6 —
175265 B/s и 25.303 с; cap 8 — 45087 B/s, все четыре probes опоздали.
Это не доказанный оптимум, причинное ускорение или готовность к звонкам:
последовательные точки использовали разные маршруты, клиенты разделяли router,
повторного baseline не было. Default не увеличен; методика, полные результаты
и ограничения находятся в [исследовании](../performance-anonymity.md).

Изменения startup/prewarm, ограничения ресурсов и проверенные сценарии описаны
в [матрице native/browser](../startup-performance.md); измеренного выигрыша
времени запуска пока нет. Успешные исторические browser-owned I2P тесты и
отсутствие network config в проверенных Pages deployments — разные результаты,
разобранные в [истории размещения](../browser-network-deployment.md).

Статический аудит обнаружил ещё не исправленные ограничения DHT: seen может
фиксироваться до обработки входящего сообщения; повторный сбор охватывает
не весь срок хранения; суммарные бюджеты пагинации и учёт пустых записей
недостаточны. Остались вопросы отмены lookup и актуальности prekey bundle.
Подробности: [доставка](../audits/dht-lifecycle-2026-11-16.md),
[ресурсы](../audits/dht-resources-2026-11-16.md).

Экспорт/восстановление резервных копий ещё требует исправления обработки
attachment paths, ошибок чтения и отката частично созданного профиля.
Успешные общие тесты не означают, что эти ограничения устранены.

Проверки платформ, происхождение бинарников и контрольные суммы относятся к
конкретному SHA, из которого GitHub Actions собирает этот выпуск. Наличие
alpha.1 страницы без файлов не используется как доказательство предыдущей
проверки бинарников.

Native baseline `6c0313e7bac2c231e9bf5e73d953a2dec22dd5e4`:
optional job [updater through the outproxy (live)](https://github.com/gluckdev/gipny-i2p/actions/runs/43874857745/job/133325113452)
завершился **failure**. В полном логе 2026-11-16 outproxy получил ответ GitHub;
в 13:27:54 UTC проверка остановилась: `no stable release yet` — нет
stable release с файлом для скачивания. Это не compile/router regression и
не успешная проверка установки обновления. Публикация alpha.2 как prerelease
не создаёт stable `/releases/latest` и сама по себе этот blocker не устраняет.
Остальные jobs оцениваются отдельно; этот красный optional результат не скрыт
и не засчитан как успех updater.
