# План реализации: Фоновое автообновление и фикс удержания сети на Android

**Цель:**
1. Убрать ручную кнопку «Проверить обновления» из UI — приложение обязано обновляться полностью автоматически по мере выхода релизов на каждой поддерживаемой платформе.
2. Сохранить и применить фикс сна на Android (WakeLock / WifiLock / Doze / Whitelist), чтобы I2P не рвался при блокировке экрана.

---

## 1. Автообновление (Desktop & Mobile)

### Текущее состояние
- В `libcore/src/update.rs` и `core/src/core.rs` фоновый цикл проверки уже есть (`UPDATE_CHECK_INITIAL_SECS = 30s`, далее каждые 6 часов с экспоненциальным backoff при ошибках).
- Автоматическая установка работает для:
  - Linux AppImage (`replace_running_appimage`)
  - Windows (`apply_staged_windows_installer` на следующий запуск)
  - `gipny-agent` (tar.gz распаковывается на лету)
- Ручные ограничения / проблемы:
  1. В `ui/src/settings.ts` (строки 131–165) есть кнопка «Проверить обновления». Пользователю не нужно ничего нажимать вручную.
  2. Linux `.deb` и Android считаются «needs_a_person» (`core/src/core.rs:1793`):
     - `.deb` требует `pkexec` (рут/пароль через polkit). При этом скачивание должно происходить в фоне, а при выходе нового релиза пользователю должно предлагаться однократное системное подтверждение/уведомление без требования заходить в настройки и кликать «Проверить».
     - Android: в текущем коде `update_configured` возвращает `false`, потому что проверка завязана на HTTP outproxy I2P, которого на Android нет (`libcore::i2p_http::OUTPROXY`). На Android релиз скачивается через APK sideload. Для полноценного автообновления Android нужен автоматический intent на установку скачанного APK через `FileProvider` (`PackageInstaller` / `ACTION_VIEW` с `application/vnd.android.package-archive`).
  3. Если релиз найден, фоновый таймер должен сразу скачивать артефакт в фоновом режиме, верифицировать SHA256 и готовить установку.

### Задачи по автообновлению
1. **Удалить ручную кнопку из интерфейса (`ui/src/settings.ts`):**
   - Убрать кнопку «Проверить обновления» и связанный с ней блок ручного запуска `Api.checkUpdate()`.
   - Оставить только статус: отображение текущей версии и, если обновление уже скачано/готово к перезапуску, ненавязчивый индикатор «Обновление готово, перезапустите приложение» (или кнопку «Перезапустить сейчас»).
2. **Гарантировать автоматический запуск скачивания и обновления:**
   - В `core/src/core.rs:1794`: при нахождении новой версии скачивание должно начинаться автоматически сразу после обнаружения.
   - Для платформ с поддержкой in-place (AppImage, Windows): стадия загрузки и подмены происходит в фоне.
   - Для Android: скачивание APK в кэш и вызов системного установщика (`Intent.ACTION_VIEW` / `Intent.ACTION_INSTALL_PACKAGE` через `FileProvider`, который уже прописан в `AndroidManifest.xml`).
3. **Проверка доступности апдейтов на Android:**
   - Разобраться с проверкой релизов на Android: поддержать запрос к GitHub Releases API (через I2P или прямой fallback, если разрешено настройками сети для обновления).

## 2. Фикс удержания I2P при блокировке экрана (Android)

Код уже подготовлен и проверен, необходимо зафиксировать в репозитории:

### Изменения в `core/gen/android/app/src/main/java/app/gipny/GipnyService.kt`:
1. `acquireLocks()`:
   - Взятие `PowerManager.PARTIAL_WAKE_LOCK` с тегом `"gipny:i2p-router"` — CPU продолжает выполнять потоки роутера при выключенном экране.
   - Взятие `WifiManager.WifiLock` (`WIFI_MODE_FULL_LOW_LATENCY` на API 29+ или `WIFI_MODE_FULL_HIGH_PERF` на старых версиях) — Wi-Fi радиомодуль не уходит в глубокий сон.
2. `releaseLocks()` в `onDestroy()`: безопасное освобождение локов при остановке сервиса.
3. `watchIdleMode()` / `unwatchIdleMode()`:
   - Регистрация `BroadcastReceiver` на `ACTION_DEVICE_IDLE_MODE_CHANGED`.
   - При выходе устройства из Doze mode роутер мгновенно уведомляется (`nativeNetworkChanged(false)` -> `nativeNetworkChanged(true)`), форсируя проверку пиров и восстановление туннелей.

### Изменения в `core/gen/android/app/src/main/java/app/gipny/MainActivity.kt`:
1. Исправление логики `maybeRequestBatteryWhitelist()`:
   - Убрать баг, когда флаг `battery_optimization_asked = true` выставлялся даже при отказе пользователя.
   - Проверять `isIgnoringBatteryOptimizations` на старте; повторно запрашивать диалог не чаще 1 раза в 24 часа, пока оптимизация не отключена.
