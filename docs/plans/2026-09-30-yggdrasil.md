# Yggdrasil: приложить бинарь и поднимать самому

## Что есть сейчас

Флаг `--meshnets.yggdrasil` в i2pd настоящий, а не декоративный: пин
`5d2bd1d299a1` (2.61.0-658) его поддерживает
(`third_party/i2pd/libi2pd/Config.cpp:396`).

Но yggdrasil i2pd **не запускает и запускать не умеет**. Он ищет уже
существующий локальный интерфейс:

```cpp
// third_party/i2pd/libi2pd/util.cpp:783
boost::asio::ip::address_v6 GetYggdrasilAddress ()
{ return GetLocalIPV6Address ([](const uint8_t addr[16]) { return IsYggdrasilAddress (addr); }); }
```

Не нашёл — пишет `Yggdrasil is not running. Disabled` и продолжает только по
обычному IP (`Transports.cpp:1587`). То есть настройка «включено» сегодня
означает «работать, только если кто-то уже поднял узел за меня». Дыра ровно та,
о которой идёт речь.

## Чем измерять «i2p недоступен»

Готового сигнала нет: `i2p_embed` не отдаёт **ничего** — ни туннелей, ни пиров,
ни статистики. Набор C-экспортов (`i2p-embed/src/lib.rs:36-56`) —
init/start/stop/set_online плюс операции с destination.

Брать лог i2pd и искать строки — плохо: формат не наш и сломается.

Есть чистый сигнал в процессе. `NetDb` — глобальный объект
(`NetDb.hpp:210`, `extern NetDb netdb;`) со счётчиком:

```cpp
int GetNumRouters () const { return m_RouterInfos.size (); };   // NetDb.hpp:118
```

Пустой netDb означает одно: мы ни разу не достучались до сети — резид
не прошёл. Это и есть «i2p недоступен» в смысле, который тут нужен.

**Важное уточнение про смысл сигнала.** Это «мы дотянулись до сети», а не
«построены туннели». netDb наполняется от первых же пиров, поэтому 5 килобайт
данных уже означают «сеть есть». Для нашей задачи это ровно тот сигнал, который
нужен: если резид не прошёл, обычный IP заблокирован и есть смысл пробовать
меш.

**И оно снимает вопрос про рестарт.** Раньше я возражал, что перезапуск роутера
рвёт туннели. При этом срабатывании туннелей нет — сеть недоступна, именно
поэтому и сработало. Перезапуск в этот момент не стоит ничего.

## План

### 1. Сигнал в шиме

`i2p-embed/shim/shim.cpp` — в этом же репозитории (сабмодуль i2pd трогать не
надо), и он линкуется с libi2pd, поэтому до `i2p::netdb` дотягивается:

```c
int gipny_router_netdb_routers(void);   // 0 = до сети не дошли
```

Плюс `gipny_router_stop` уже есть — значит, у нас есть и остановка, и старт,
то есть перезапуск роутера целиком умещается в существующий API.

### 2. Узел yggdrasil как процесс

- бинарь едет в сборку рядом с приложением (шаг 4);
- `libcore/src/net.rs`: перед стартом i2pd найти бинарь, поднять
  (`tokio::process::Command` уже используется в `libcore/src/agent.rs:20`),
  дождаться появления интерфейса, и только потом стартовать i2pd с флагом;
- узел — ребёнок процесса приложения, умирает вместе с ним, чтобы не осталось
  висящего TUN.

### 3. Порог

После старта роутера: если через N секунд netDb всё ещё пуст, а режим не
`off` — поднимаем ygg и перезапускаем роутер с флагом.

N требует подбора по факту, а не с потолка: холодный старт на нормальной сети
тоже занимает время до первых пиров. Зашивать будущее число плохо; сначала
измеряем.

### 4. Бандлинг

Релизный воркфлоу кладёт бинарь под каждую платформу. Отдельно: **yggdrasil
распространяется под GPL-3.0**. Это само по себе нормально — отдельный процесс,
не связанный бинарно, — но при раскладке надо дать ссылку на исходники. В
корне репозитория файла `LICENSE` вообще нет, так что нынешняя позиция проекта
по лицензированию мне неизвестна.

## Android — отдельная история

Выбрано «портировать и на Android сейчас». Честно о цене: официальных сборок
yggdrasil под Android нет, и это не порт.

Ключевое требование — TUN-интерфейс. Без root приложение не может создать его
само: единственный путь — `VpnService`. А это значит:

- gipny на Android становится VPN-приложением;
- системный диалог разрешения VPN при каждом подключении, и запись в настройках
  системы;
- маршрутизация трафика — решение приложения, вместе с защитой собственных
  сокетов i2pd через `protect()`.

То есть desktop-часть всё равно нужна первой: и шим, и определение недоступности,
и запуск узла — общее. Android добавляет сверху слой с TUN, разрешениями и
foreground-сервисом, а не заменяет его.

Порядок: сначала desktop целиком, потом Android-слой.
