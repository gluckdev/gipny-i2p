# Локальный веб-режим: проверка реализуемости

Дата: **2026-10-31**, уточнение review T9b: **2026-11-01**. Статус: реализация эксперимента, не релиз.

## Требование владельца

Веб-версия gipny полностью работает на машине пользователя и запускается через
браузер; loopback-порт допустим. На первом шаге ключи и криптография остаются
в нативном процессе. Тот же интерфейс должен стартовать со статического GitHub
Pages. Хостинг никогда не должен получать переписку, даже шифротекст.

## Наблюдение в исходном коде

Исходный `gipny-web` был hosted gateway: публичный bind, серверное правило одного
хопа, permissive CORS, без capability и Origin/Host. `dispatch_rpc` уже делил
Core с desktop, но не обеспечивал полную совместимость команд UI. Vault-lock
в `libcore/src/security.rs` явно process-local; Tauri single-instance plugin
не координирует отдельный web binary. Project Pages использует `/gipny-i2p/`;
`site/build.mjs` копирует относительные ресурсы без собственного backend.

## Реализованный дизайн

По умолчанию `127.0.0.1:0`; `--port N` закрепляет порт, loopback `--listen`
также включает local policy (loopback нормализуется в IPv4 `127.0.0.1`).
`--port` и `--listen` вместе отклоняются. Случайный capability на запуск, приватная
ссылка в stderr и открытие системного браузера (`--no-open` отключает).
`GIPNY_SERVER_HOPS` удаляется; каталог совпадает с resolver desktop.
`--pages [URL]` меняет только страницу запуска, по умолчанию
`https://gluckdev.github.io/gipny-i2p/app/`. Порт/токен передаются fragment,
удаляются history API и сохраняются в sessionStorage вкладки только после
успешного `web_info`. Первоначальный отказ виден в форме; неудачный submit
отключает фоновые retry и сохраняет введённые поля. Браузер
соединяется только с loopback; сначала сопряжение и `web_info`, потом bootstrap.
При отказе доступна форма RU/EN; три быстрых разрыва останавливают reconnect.

`build_router(state, static_dir, Some(LocalPolicy))` и `serve(listener, router)`
публичны. Router создаётся без Core. Все маршруты проверяют точный Host,
WebSocket дополнительно проверяет capability и обязательный allowlisted Origin.
Ответы имеют no-store/no-referrer/nosniff, HTML — CSP с текущим loopback портом.
CORS в local mode не нужен. Pages meta CSP разрешает loopback WebSocket и все
источники Tauri; landing CSP остаётся `connect-src 'none'`.

`instance.lock` в base dir — постоянный пустой файл с OS advisory lock через
`File::try_lock`; guard хранит `File`, не PID/sentinel. Kernel освобождает lock
при Drop или смерти процесса, ручная очистка не нужна. Web при невозможности
захвата отказывает с именем каталога. Desktop пытается best-effort, при ошибке
логирует warning и продолжает прежний запуск; desktop-vs-desktop обрабатывает
single-instance plugin. Взаимное исключение с desktop, запущенным вторым,
не гарантируется. Mobile gating сохранён.
Файлы в браузере остаются в памяти до передачи через attachment RPC; оба web
send arm используют общие desktop helpers и настройку privacy для очистки
метаданных. Тест без Core проверяет удаление JPEG APP1, отклонение HEIC и
сохранение байтов при выключенной очистке. WebSocket default limits: 64 MiB на
всё JSON-сообщение и 16 MiB на кадр; base64 добавляет примерно 1/3 размера.
Превышение закрывает WebSocket, большие файлы с диска — отдельный desktop-путь.
Скачивание — Blob. Notifications запрашивают разрешение при первой отправке
из пользовательского действия; bootstrap только читает permission, toast — при denied.
Desktop backup import/export и сохранение APK дают видимую подсказку вместо
вызова Tauri: web RPC этих методов не реализовывал.

Только явный non-loopback `--listen` сохраняет опасный legacy hosted mode с предупреждением,
permissive CORS и серверными hop-настройками. Это не требование владельца.
`--allow-origin` парсится как http(s) origin без пути/query/fragment/userinfo,
нормализуется в нижний регистр; завершающий `/` и пути отклоняются явно.
Нативный процесс вызывает `harden_process()` до работы с секретами. Browser
launcher запускается через `spawn` с отключёнными stdio; ожидание child вынесено
в отдельный поток и не задерживает обслуживание listener.

## Что проверяют тесты

Rust integration `web_local` слушает настоящий ephemeral TCP loopback с маленьким
HTML fixture, без Core/I2P: неверный Host на static/health/fallback/ws → 403;
правильный Host → 200 и защитные заголовки; неверный/отсутствующий токен → 401;
неверный/отсутствующий Origin → 403; local/localhost/Pages/custom Origin → 101;
`web_info` возвращает local/version до unlock. Отдельная проверка доказывает
WouldBlock на втором отдельном File handle, повторный захват после Drop и
переиспользование lock-файла. Дополнительные проверки покрывают mapping `--port`
и loopback `--listen`, нормализацию/отказ неверного Origin; listener-тест повторно
проверяет Host/token/Pages WS на закреплённом порту. Сравнение токенов
использует полный цикл без выхода по несовпадению; timing side channel тестом
не измеряется.

UI unit tests собирают реальные TS-модули Vite и используют happy-dom: endpoint
local/Pages, pairing при неполных данных, scrub fragment, сохранение в пределах
вкладки, ограничение повторов и inline attachment bytes. Регрессия сопряжения
проверяет видимый initial failure, отсутствие сохранения до успешного web_info
и отмену retry при ошибке submit без стирания набранного текста. Форма использует существующие
RU/EN словари; реальный браузер требует отдельной проверки. Они
не моделируют browser network permissions или mixed-content enforcement.
Site tests сохраняют политику landing и отдельно проверяют packaging app/.
Linux security-fast запускает Rust integration и отдельный тест sanitizer без Core;
UI и Pages jobs запускают npm test. Проверка уведомлений подтверждает отсутствие
запроса/подсказки при bootstrap, один запрос при первой отправке и подсказку только
при denied; реальную user activation happy-dom не моделирует.

Это описание проверяемых утверждений, не заявление об успешном CI-запуске.
Фактические локальные команды и их результаты находятся в `REPORT-T9.md`
рабочей ветки и `REPORT-T9b.md`; CI следует оценивать по конкретному запуску после review.
Владелец сообщил до T9b об успешных прежних 3 Rust/6 web UI тестах и smoke вне
sandbox; это внешний результат до этих исправлений, не проверка новой версии.

## Модель доверия и границы

Capability даёт полный доступ к RPC, включая управление vault. Любой локальный
процесс может обращаться к loopback и подделывать HTTP headers. Проверки
зависят от секретности bearer-токена и ограничений ОС; это не изоляция локальных
пользователей. Автозапуск передаёт URL в argv launcher/браузера; world-readable
`/proc/*/cmdline` может раскрыть токен до завершения браузера. Fragment попадает
в историю до `replaceState`, и история/синхронизация/расширения могут его сохранить.
На многопользовательских машинах рекомендуется `--no-open`: открыть UI без
fragment, ввести порт/токен через форму и не сохранять stderr в общих логах.
`harden_process` снижает риск дампа/доступа к памяти native process, но не скрывает
argv/историю браузера и не защищает от привилегированного процесса. Скомпрометированный браузерный профиль/расширение видит
plaintext. Pages JS — доверенная цепочка поставки UI и также видит данные после
сопряжения. Origin `https://gluckdev.github.io` охватывает все project sites
этого origin. Дополнительные Origin следует давать только своему UI.
Отсутствие отправки переписки хостингу — свойство текущих маршрутов/кода,
не защита от подмены доверенного JS. Для минимального доверия к hosting
используется локально раздаваемый UI.

## Не проверено и решения владельца

- Реальные Chrome/Firefox: HTTPS Pages → `ws://127.0.0.1`, mixed content,
  Chrome local-network permission, отказ пользователя и восстановление.
- Запуск браузера и освобождение advisory lock после разных видов завершения
  процесса на Windows/macOS.
- Реальный профиль, разблокировка, маршрутизатор/I2P, переписка, совместная
  попытка запуска с desktop, старые desktop-версии, аварийное завершение.
- Android и мобильные браузеры. Этот эксперимент ориентирован на desktop.
- Полное покрытие web RPC всеми возможностями UI: task не меняет существующий
  dispatcher в целом, кроме handshake и исправления privacy для вложений. Ошибки старых отсутствующих методов
  остаются ограничением эксперимента.
- Публикация Pages, упаковка/доставка отдельного бинаря и shipping build.

План следующего решения: проверить реальные браузеры и OS lifecycle до обещаний
пользователям; решить, продолжать ли поддержку legacy hosted gateway, доверять
ли всему Pages origin и какие desktop-only операции переносить в web RPC.
