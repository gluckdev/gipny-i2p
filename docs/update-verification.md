# Обновления: обязательная проверка SHA256

Состояние на **2026-10-28**: ветка `fix/required-update-checksum`; изменение
выпущено в `v0.4.19` (2026-10-29). База сравнения — `main`
`26487a5ca213c4ccbbd372038d14a71e17ca6314`.

## Изменение поведения

В базовой версии отсутствие `SHA256SUMS.txt`, ошибка его загрузки или отсутствие
строки для выбранного файла превращаются в `None`. `download_asset_to` при этом
пропускает проверку, а успешный результат может попасть в установку. Отдельная
кнопка сохранения APK всегда передаёт `None`.

В новой версии каждое обновление и каждое сохранение APK требуют валидной
контрольной суммы. Сбой получения суммы останавливает операцию и возвращает
ошибку вызывающему коду. Агент, приложение и проверка обновлятора в e2e-харнессе
используют один обязательный контракт:

1. Для выбранного файла берётся `SHA256SUMS.txt` из того же `ReleaseInfo`.
   `Updater::asset_sha256` требует единственный manifest; ошибка HTTPS
   передаётся вызывающему коду.
2. Каждая непустая строка manifest имеет 64 шестнадцатеричных символа, пробел,
   признак текстового/бинарного режима и точное имя файла. Поддерживаются
   `hash  filename`, `hash *filename`, верхний регистр hex, LF и CRLF.
   Повторяющиеся имена, повреждённые строки и отсутствие выбранного файла
   являются ошибкой. Полнота списка остальных файлов релиза не требуется.
3. `Sha256Digest` хранит проверенную сумму; его поле закрыто, а
   `UpdateInfo::sha256` и параметры download API больше не принимают `Option`.
   Передать `None` для обхода проверки нельзя.
4. Скачивание записывает байты в отдельный временный файл в каталоге назначения.
   Проверяются фактический размер против `ReleaseAsset::size` и SHA256 всех
   байтов. Только после обеих проверок файл назначения атомарно заменяется и
   его путь возвращается вызывающему коду для установки или сохранения.

Размер release JSON ограничен 4 МиБ, manifest — 1 МиБ, артефакта — 1 ГиБ.
Ограничения текстовых ответов действуют во время чтения, включая ответы без
`Content-Length` и с `Transfer-Encoding: chunked`.

## Ошибки и временные файлы

Несовпадение SHA256, несовпадение размера, обрыв HTTP, ошибка записи или
переименования сохраняют прежний файл назначения. Временным файлом владеет
`NamedTempFile`: он удаляется при ошибке и отмене future. Разные скачивания
не используют общий путь `.partial`; удаление старого файла перед успешной
проверкой больше не выполняется.

Это поведение распространяется на `Updater::download`, ручное сохранение APK
и вызовы `download_asset`/`download_asset_to`. Цикл агента продолжает устанавливать
только результат успешного `download`. E2e-сценарий выбирает самый маленький
артефакт, исключая сам `SHA256SUMS.txt`, и проверяет его по manifest того же
релиза. Контрольная сумма manifest внутри самого себя не требуется.

## Совместимость и границы доверия

Workflow релиза уже создаёт стандартный `SHA256SUMS.txt` через `sha256sum` и
публикует release после загрузки файлов. Формат существующих manifest не
меняется. Новый updater отказывается скачивать релиз без подходящей суммы;
возврата к скачиванию без проверки нет. Формат сообщений, криптография переписки
и поведение установщиков не меняются.

SHA256 с той же страницы GitHub проверяет целостность относительно этой
страницы. Это **не независимая подпись** издателя, не TUF и не защита от
компрометации release publisher. HTTPS по-прежнему идёт через собственный поток
I2P к outproxy с TLS до GitHub и корнями `webpki`; прямое IP-соединение при
отказе I2P не добавлено.

## Проверка

Проверено **2026-10-28**, Rust `1.93.1`: `update::tests` — **14/14**
(11 новых и 3 существующих). Используется настоящий HTTP-парсер `hyper` поверх
`tokio::io::duplex`, без слушающего порта и роутера. Проверены отсутствие,
ошибка загрузки, повреждение и неоднозначность manifest, ограничение текстового
ответа, chunked-скачивание, неверные SHA256 и размер, обрыв, отмена операции,
сохранение прежнего файла и очистка staging при ошибке замены.

```bash
env -u CC -u CXX I2P_EMBED_STUB=1 cargo test --locked -p gipny-libcore --lib update::tests
env -u CC -u CXX I2P_EMBED_STUB=1 cargo check --locked -p gipny-agent -p gipny-bot -p e2e-harness --all-targets
```

Обе команды проходят в локальном окружении с заглушкой нативного роутера и
доступными сертификатами i2pd (`I2P_EMBED_CERTS_DIR`). Живой I2P, установка на
устройства и сборка `Core` этими результатами не подтверждаются.
