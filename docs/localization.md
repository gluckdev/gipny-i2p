# Локализация: 8 языков интерфейса и сайта (`ru`, `en`, `uk`, `de`, `km`, `vi`, `hi`, `zh`)

Проверено по исходникам 2026-11-08. Базовая локализация RU/EN выпущена в `v0.4.19`
(2026-10-29); в ветке `feat/own-keyboard` (2026-11-08) интерфейс приложения и
публичный сайт расширены до 8 языков: русский (`ru`), английский (`en`),
украинский (`uk`), немецкий (`de`), кхмерский (`km`), вьетнамский (`vi`),
хинди (`hi`) и китайский (`zh`).
[English project guide](../README.en.md).

## Поведение

- Язык доступен на экранах выбора, создания и разблокировки профиля, при
  загрузке и в настройках (компактная двухколоночная сетка `.language-options`).
  Выбор не требует открывать vault.
- `gipny.lang` в `localStorage` хранит один из 8 кодов: `ru`, `en`, `uk`, `de`,
  `km`, `vi`, `hi`, `zh`.
  Порядок выбора по умолчанию (одинаковый в приложении `ui/src/i18n.ts` и на
  сайте `site/main.js`):
  1. Явный выбор (`localStorage` `gipny.lang` в приложении / `?lang=` на сайте).
  2. Русский (`ru`) при русской локали среди предпочтительных языков
     (`navigator.languages`, `navigator.language`, локаль `Intl`) или русской
     системной раскладке клавиатуры (`ы`, `ъ`, `э` в `navigator.keyboard.getLayoutMap()`).
  3. Первый совпавший тег из списка системных языков (`navigator.languages` +
     `Intl`), причём если первым совпал `en`, а в системе обнаружена
     неанглийская раскладка клавиатуры (`uk`, `de`, `km`, `vi`, `hi`, `zh`),
     приоритет получает язык системной раскладки.
  4. Язык обнаруженной системной раскладки клавиатуры (`detectKeyboardLang`).
  5. Английский (`en`).
  Автоматическое определение не сохраняется; отложенная проверка раскладки
  не переопределяет явный выбор, сделанный во время ожидания.
  При недоступном storage интерфейс
  работает с выбором в памяти. Даже совпадающий с автоматическим явный выбор сохраняется.
- Меняется также `document.documentElement.lang`, даты списка чатов, длительности,
  статусы, подсказки и атрибуты доступности. Приложение не перезагружается и не
  блокирует профиль. Черновик, прикреплённые файлы, ответ, редактирование и история
  консоли остаются в памяти; в `localStorage` эти данные не переносятся.
- Содержимое сообщений, имена, файлы, карточки, команды и их вывод не переводятся.
  Текст release notes приходит извне и сохраняется как опубликован. Системные
  диалоги разрешений и выбора файла переводит ОС. Неизвестная диагностика
  сохраняется в исходном виде; известные русские ошибки sanitizer/installer
  для нерусских локалей отображаются через `errorText` без изменения
  значений IPC.

## Где менять

| Файл | Ответственность |
|---|---|
| `ui/src/locales/{en,ru,uk,de,km,vi,hi,zh}.ts` | Словари интерфейса (8 языков); одинаковые ключи и параметры подстановки |
| `ui/src/i18n.ts` | `LANGS` с названиями языков на самих языках, `detectLang`, `detectKeyboardLang`, `detectSystemLangs`, предпочтение, `getLocale`, `setLang`, подписки, `t` |
| `site/main.js`, `site/index.html` | Словари сайта на тех же 8 языках (`messages`), `resolveLanguage`, `detectKeyboardLanguage`, переключатель и Open Graph `og:locale` |
| `ui/src/language-picker.ts` | Выбор языка до входа |
| `ui/src/app.ts` | Перерисовка активного представления и освобождение дочерних views |
| `ui/src/chat.ts` | Сохранение и восстановление состояния ввода при смене языка |
| `ui/src/avatars.ts`, `auth.ts` | `avatarNames()` и `bootLabels()`: подписи вычисляются при показе |
| `ui/src/error-text.ts` | Только отображение известных ошибок старого backend; не протокол |
| `ui/tests/localization.test.mjs` | Проверка переводов и поведения настоящих UI-компонентов в DOM |
| `ui/dev/mock.ts`, `preview.html` | Превью `lang=en\|ru\|uk\|de\|km\|vi\|hi\|zh`, селекторы по актуальным переводам |

Все словари проверяются TypeScript по ключам русского (`satisfies Record<keyof typeof ru, string>`).
`npm test` дополнительно сравнивает каждый из 8 словарей из `translations` с английским:
совпадение ключей и параметров подстановки, непустые строки; проверяет отсутствие
случайно оставшегося русского текста в нерусских экранах.
Названия языков в переключателях берутся из `LANGS`
и всегда остаются на языке самой локали.

Для нового языка добавьте полный словарь в порядке ключей `en.ts` с проверкой
`satisfies Record<keyof typeof ru, string>`, затем добавьте его импорт, запись
в `translations`, вариант `Lang`, название в `LANGS` и локаль дат в `locales`
модуля `i18n.ts`. Переключатели и проверки словарей перебирают общие списки;
автоопределение проверяет языки по списку `navigator.languages` и `Intl`, а также
активную раскладку `navigator.keyboard.getLayoutMap()` (там, где браузер её отдаёт),
с русским в приоритете и английским как запасным вариантом.

## Добавление текста

Добавь один устойчивый смысловой ключ и версии строки во всех 8 словарях; вызывай
`t('ключ', { name: value })`. Перестраиваемое предложение должно быть одной
строкой с параметрами, а не набором фрагментов, зависящих от порядка слов.
Не вычисляй переводы в константах модуля: иначе они останутся на языке первого
импорта. Не меняй протокольные enum, ключи БД, названия файлов или команды ради
перевода. Не интерпретируй перевод или пользовательский текст как HTML.

Интерполяция выполняется одним проходом через callback `replace`: `$&`, `$'`,
`$`` и `{name}` внутри имени или ошибки остаются буквальным текстом, без повторной
подстановки. Ошибки с именем файла сохраняют само имя.

Пояснения безопасности переводятся с проверкой фактов: роутер теперь внутри
процесса, а не через SAM; удаление сообщений не отзывает сделанные копии;
checksum с той же страницы не является независимой подписью релиза. Одну
формулу нельзя усиливать относительно другой локали.

## Проверки и пределы

Из `ui/`: `npm ci`, `npm run build`, `npm test`. Сценарии проверяют выбор
локали и отказ хранилища, отложенное определение раскладки, все 8 словарей,
буквальную интерполяцию, ошибки, смену языка
до входа, сохранение состояния чата и отсутствие накопления подписок,
модальные окна на всех 8 языках. Тестовый модуль собирается Vite, DOM
предоставляет `happy-dom`; аккаунт, роутер и сеть не используются.

Ручное превью: `/dev/preview.html?scene=settings&lang=en` (или любой из 8 кодов `ru`, `en`, `uk`, `de`, `km`, `vi`, `hi`, `zh`), затем
`chat`, `console`, `auth`, `boot`, `identity`, `add-contact` на узких экранах.
DOM-тест не измеряет CSS-переполнение и не проверяет камеру/разрешения реального
Android. Нативные установщики и живая I2P-доставка этим изменением не проверялись.

Документация поддерживается постоянно: изменение UI, сообщения об ошибке или
обещания безопасности требует синхронного обновления всех локалей, затронутого
README, проверок и блоба. Новые найденные ограничения и восстановленные ссылки
фиксируются с источником и пределами проверки.
