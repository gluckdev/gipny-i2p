# gipny (i2p)

Анонимный мессенджер со сквозным шифрованием для десктопа и мобильных. Без телефона, без email, без логина. Личность — это пара ключей ed25519/x25519, и больше ничего; сетевой i2p‑адрес **эфемерный** — генерируется заново на каждую сессию.

> **Про форк:** это **i2p‑форк** gipny. Транспорт переведён с Tor (Arti) на **i2p** (через i2pd и SAMv3). Крипта, хранилище, протокол релея и UI не менялись. Полный список изменений и текущий статус — в **[MIGRATION-i2p.md](MIGRATION-i2p.md)**.
>
> Форк — **отдельное приложение** (`app.gipny.i2p`, имя `gipny-i2p`, свой каталог данных) и ставится **рядом** с оригинальным gipny, не заменяя его; профили и переписка между ними не разделяются.

> ⚠️ **Статус. Опубликованные релизы (v0.3.4 и раньше) собраны с go‑i2p и не
> доставляют сообщений.** go‑i2p не достраивает клиентские туннели: ни одно
> сообщение не дошло ни в CI, ни на живой машине. Роутер заменён на **i2pd**,
> с которым тот же стенд доставил 5 из 5 сообщений за 49 секунд, но **сборки с
> i2pd ещё не выпущены**. Замеры и причины:
> **[docs/i2p-transport-evaluation.md](docs/i2p-transport-evaluation.md)**.
>
> Отдельно: подозрение, что go‑i2p публиковал LeaseSet с нашим IP, по разбору
> исходников **не подтвердилось**
> ([docs/go-i2p-leaseset-analysis.md](docs/go-i2p-leaseset-analysis.md)) — но
> проверка была только по коду, не по реально опубликованному LeaseSet.
>
> **Не использовать для задач, где нужна реальная анонимность.**

- **Транспорт:** i2p через встроенный роутер **i2pd** (SAMv3), из Rust общаемся крейтом `yosemite`. Роутер поставляется внутри приложения — ставить отдельно ничего не нужно.
- **Крипта:** первичный обмен X3DH + Double Ratchet (те же примитивы, что у Signal), AEAD XChaCha20‑Poly1305, Ed25519 + X25519.
- **Хранилище на диске:** SQLCipher (AES‑256) с KDF Argon2id. Пароль под принуждением (duress: стереть или подсунуть decoy), авто‑стирание при переборе, харднинг процесса (без core dump, mlock).
- **Минимизация метаданных:** sealed sender (`from = [0u8; 32]` в проводе — релей не видит отправителя), паддинг полезной нагрузки по фиксированным «корзинам» (размер не выдаёт текст/вложение/медиа).
- **Доставка:** один центральный «слепой» релей поверх i2p — никогда не P2P напрямую, но офлайн‑доставка работает (релей держит зашифрованные блобы, пока адресат не в сети).
- **Bot SDK:** полноценный Rust‑крейт для ботов: текст, файлы (мультивложения), inline‑кнопки — всё по тому же зашифрованному каналу.

## Как устроен транспорт

Приложение содержит бинарь `i2pd`, собранный из `third_party/i2pd`. При запуске приложение поднимает его дочерним процессом на свободном локальном порту (по умолчанию `127.0.0.1:7656`) с выключенными консолью, прокси и UPnP, ждёт готовности SAMv3 и дальше автоматически гоняет весь трафик через i2p. Устанавливать вручную ничего не надо. На Android отдельного процесса нет — i2pd живёт внутри процесса приложения через JNI (см. раздел про Android).

**Адрес эфемерный.** На каждый запуск генерируется новый i2p‑destination (SAM `DEST GENERATE`); на диск он не пишется, приватный ключ живёт только в памяти (в `Zeroizing`). Стабильная личность — ключи ed25519/x25519 в зашифрованном хранилище: релей маршрутизирует по ним, а не по i2p‑адресу, поэтому смена адреса ничего не ломает, а сессии не связываются между собой на сетевом уровне. В карточке личности показываются и полный base64‑destination, и короткий `.b32.i2p`‑адрес.

**Только исходящие.** Клиент работает с `publish: false` — LeaseSet не публикуется, входящие туннели не поддерживаются: вся доставка и так идёт через релей, а холодный старт заметно быстрее. Входящий `STREAM FORWARD` по умолчанию выключен и включается переменной `GIPNY_I2P_ACCEPT=1`.

Цепочка: `ты → i2p‑туннели → релей gipny → destination получателя`. Первый запуск дольше последующих (i2p делает reseed и строит туннели, это 1–3 минуты). Системный VPN до запуска добавляет ещё один слой между твоим реальным IP и входом в i2p.

> Прежняя опция внешнего SOCKS5‑прокси удалена: в i2p трафик до локального роутера идёт по loopback, а маршрутизацией между узлами занимается сам роутер.

```
приложение (Rust) ──SAMv3 127.0.0.1:7656──▶ i2pd (C++)
                                              ├─ роутер i2p
                                              └─ SAMv3‑мост
```

> ⚠️ **Пока брать оттуда нечего.** Все опубликованные релизы (по v0.3.4

> Инструкции ниже описывают, как это будет работать после первого релиза на
> i2pd; сегодня единственный рабочий путь — собрать из исходников.

### Linux

```bash
# AppImage (без установки, просто запуск)
chmod +x gipny-i2p_*.AppImage
./gipny-i2p_*.AppImage

# .deb (Debian / Ubuntu / Parrot / Mint / Kali)
sudo apt install ./gipny-i2p_*_amd64.deb
```

### Windows

- `gipny-i2p_*_x64-setup.exe` — установщик NSIS.

Установщик кладёт приложение в свой каталог `gipny-i2p` и создаёт ярлык в меню «Пуск» — с оригинальным gipny не пересекается.

### macOS

- `gipny-i2p_*_aarch64.dmg` — Apple Silicon (M1 и новее).
- `gipny-i2p_*_x64.dmg` — Intel.

Нужна **macOS 15 (Sequoia) или новее**: роутер собирается на раннерах GitHub с
macOS 15 (образ 14 там уже снят с поддержки), и его библиотеки несут эту
минимальную версию.

Сборка **не подписана сертификатом Apple и не нотаризована** — на это нужен
платный аккаунт разработчика. Приложение подписано ad‑hoc, поэтому при первом
запуске macOS его заблокирует. Открыть: перетащи `gipny-i2p` в «Программы»,
попробуй запустить, затем открой «Системные настройки → Конфиденциальность и
безопасность» и разреши открытие под сообщением о gipny-i2p. Либо из терминала:

```bash
xattr -dr com.apple.quarantine /Applications/gipny-i2p.app
```

### Android — экспериментальная поддержка

На Android i2pd встроен непосредственно в процесс приложения через JNI:
`android-router/jni` собирает те же исходники i2pd плюс две точки входа gipny
(`nativeStartSam`/`nativeStopSam`) в `libi2pd.so` под каждую ABI; foreground
service (`GipnyService.kt`) пишет `i2pd.conf`, распаковывает reseed‑сертификаты,
загружает библиотеку и поднимает SAMv3 на `127.0.0.1:7656`, а Rust‑ядро просто
подключается к нему (`RouterHandle::attach`). Десктопный sidecar‑бинарь в APK не
попадает — `core/tauri.android.conf.json` обнуляет `bundle.resources` для этой
платформы.

Роутер не собирается из Gradle: i2pd — это C++ с boost и OpenSSL, и каждая ABI
занимает около часа. Его собирает CI (`i2pd-build.yml`, `release.yml`), а
Gradle‑таск `stageI2pdJniLibs` только раскладывает готовый `.so` по jniLibs.
Для локальной сборки положи артефакт в `android-router/prebuilt/<abi>/libi2pd.so`
или укажи каталог через `GIPNY_I2PD_JNILIBS`.

Где взять APK:
- **Релизный** (подписанный постоянным ключом, `arm64-v8a`) — со страницы
  Releases. Только начиная с первого релиза на i2pd; всё, что там лежит
  сейчас, собрано с go‑i2p и не работает.
- **Отладочный** — артефакты джобы `android APK` workflow **build**. Они
  собираются с `-PskipRouter` и **не содержат роутера**: годятся, чтобы
  проверить, что приложение ставится и стартует, но подключиться не смогут.
  Имена артефактов это отражают (`…-no-router`).

Обновляется приложение на Android через собственный update‑канал, Google Play
не используется. Канал пока не развёрнут — см. «Свой релей».

Поддержка пока считается экспериментальной до проверки на расширенной матрице
реальных устройств.

## Структура проекта

```
core/           Клиент на Tauri 2 (Rust + TS UI), десктоп и android
libcore/        Общий код: крипта, сессии, транспорт, БД, роутер
third_party/    Вендоренные сабмодули: i2pd и i2pd-android (скрипты сборки зависимостей)
android-router/ JNI-обвязка: i2pd + две точки входа gipny → libi2pd.so
bot-sdk/        Фреймворк для ботов
ui/             UI на TypeScript (ванильный, без фреймворка)
.github/     GitHub Actions: build.yml (проверка + debug-APK), release.yml (релиз),
             codeql.yml (security-скан), dependabot.yml (обновление зависимостей)
```

Локальных сборочных скриптов нет — **все сборки только на GitHub Actions**.

Каталог `core/relay/` — крейт релей‑сервера. Он специально вне основного workspace и нужен только если поднимаешь свой релей.

## Сборка из исходников

Цели: **Linux** (AppImage / .deb / .tar.gz), **Windows** (установщик NSIS / портативный zip), **macOS 15+** (dmg, Apple Silicon и Intel), **Android arm64** (экспериментальный APK).

Нужны:
- **Rust** (stable) — сам мессенджер. Ставится через [rustup](https://rustup.rs/).
- **C++‑тулчейн, boost и OpenSSL** — встроенный роутер i2pd (`third_party/i2pd`).
  Либо системный i2pd, если собирать роутер не хочется.

### Встроенный i2p‑роутер (i2pd)

Роутер вендорится сабмодулем и собирается из исходников:

```bash
git submodule update --init --recursive
cd third_party/i2pd
make USE_UPNP=no USE_GIT_VERSION=yes -j"$(nproc)"

# положи его туда, где приложение его найдёт: в core/resources (оттуда его
# берёт и tauri-bundler, и dev-запуск), рядом с бинарём gipny, или укажи путь
# через переменную GIPNY_I2P_BIN
cp i2pd ../../core/resources/
```

Для быстрой итерации сгодится и системный i2pd (`apt install i2pd`) — Rust
говорит с ним по обычному SAMv3 и не отличает один от другого:

```bash
export GIPNY_I2P_BIN=/usr/sbin/i2pd
```

> `core/resources/i2pd` должен существовать, иначе `cargo tauri build` упадёт
> ещё в build‑скрипте: `tauri.conf.json` бандлит роутер по глобу
> `resources/i2pd*`, а tauri‑build считает glob без совпадений ошибкой.

Проверка, что роутер жив:
```bash
./i2pd --datadir=$PWD/router-data --sam.enabled=true --sam.port=7656 \
       --http.enabled=false --upnp.enabled=false
# в другом окне:
printf 'HELLO VERSION MIN=3.0 MAX=3.3\n' | nc 127.0.0.1 7656   # → RESULT=OK
```

### Нативная dev‑сборка под Linux

Системные зависимости (имена для Debian/Ubuntu; в других дистрибутивах — аналоги):

```bash
sudo apt install -y build-essential pkg-config curl ca-certificates git \
    libssl-dev libgtk-3-dev libwebkit2gtk-4.1-dev \
    libayatana-appindicator3-dev librsvg2-dev libsoup-3.0-dev \
    libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
    gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
    gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly \
    gstreamer1.0-libav gstreamer1.0-pulseaudio gstreamer1.0-alsa \
    libasound2-dev nodejs npm
```

Затем:

```bash
# роутер кладём прямо в core/resources — оттуда его берёт и tauri‑bundler,
# и dev‑запуск (иначе tauri‑build ругнётся, что resources‑glob пуст)
mkdir -p core/resources
git submodule update --init --recursive
make -C third_party/i2pd USE_UPNP=no -j"$(nproc)" && cp third_party/i2pd/i2pd core/resources/
cd ui && npm install && npm run build && cd ..
cd core && GIPNY_I2P_BIN=$PWD/resources/i2pd cargo run   # dev‑запуск
```

Окно Tauri откроется, как только соберётся бинарь. Первый старт i2p — 1–3 минуты (reseed + туннели).

### Все сборки — только на GitHub Actions

Локального сборщика нет; всё делается в CI:
- **`.github/workflows/build.yml`** — проверка на каждый push/PR: Rust‑workspace + typecheck UI + джоба **android APK** — собирает debug‑APK для `arm64-v8a` и `x86_64` (эмулятор) **без роутера** (`-PskipRouter`, артефакты помечены `-no-router`) и проверяет, что Rust‑библиотека попала внутрь; следом необязательная (`continue-on-error`) джоба **android emulator smoke**. Роутер здесь не собирается: i2pd — это час на каждую ABI.
- **`.github/workflows/release.yml`** — полный релиз по тегу `v*`: собирает i2pd (Linux — статически в Alpine, Windows — msys2, Android — как `libi2pd.so` с кешем по пину сабмодуля), кладёт его в ресурсы, собирает Linux (AppImage/deb), Windows (NSIS) и **Android** (подписанный arm64‑APK; `apksigner verify` плюс проверка, что роутер и reseed‑сертификаты реально внутри APK), публикует GitHub Release.
- **`.github/workflows/codeql.yml`** — security‑скан (rust / js‑ts / actions), default‑suite.
- **`.github/workflows/e2e-i2pd.yml`** — сквозной тест «от А до Я» и единственное место, где проверяется то, ради чего всё делается: доходят ли сообщения по живой i2p. Поднимает релей и двух headless‑ботов (`bot-sdk`) поверх реальных туннелей, шлёт сообщения и меряет latency/RSS в Job Summary. Тяжёлый (15–30 мин), крутится ночью и вручную. Релей и оба бота работают на **одном общем роутере** (`GIPNY_SAM_PORT`). **Больше не `continue-on-error`**: недоставка красит джобу. Раньше галка была зелёной при нуле доставленных сообщений — именно так неработающий транспорт и остался незамеченным.
- **`.github/workflows/i2pd-build.yml`** — сборка роутера под все платформы, включая те, что не покрывает релиз (musl, armeabi-v7a, вторая Android ABI). Еженедельно.
- **`.github/dependabot.yml`** — еженедельные групповые обновления по всем экосистемам (cargo основного workspace, cargo relay, gomod, npm, actions). `core/relay` уже мигрирован на текущие мажоры (bincode 2, rand 0.10, ed25519-dalek 3, thiserror 2, rusqlite 0.40); заморожены только ломающие бампы крипто/serde‑стека в основном workspace (`libcore`/`core`/`bot-sdk`) — там протокол и формат вольта должны остаться байт‑идентичными, миграция отслеживается отдельно (issue #31).

Нюанс Android‑сборки: вендоренный OpenSSL (для SQLCipher) при кросс‑компиляции ожидает binutils‑имена `<triple>-ranlib`/`-ar`, которых в NDK r23+ нет, — workflow сам создаёт симлинки на `llvm-ranlib`/`llvm-ar`.

Android APK подписывается постоянным release‑ключом. Для release workflow нужны
GitHub Actions secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD`.

Запуск релиза: `git tag v0.3.0 && git push origin v0.3.0` (или Actions → release → Run workflow).

## Оформление

Вид приложения — в стиле дашборда Xbox: почти чёрные нейтральные поверхности,
фирменный зелёный как единственный акцент, скруглённые плитки, чистый рубленый
шрифт. Это **единственный** вид: переключателя нет, вариантов сборки нет.

Раньше это была отдельная сборка (`VITE_THEME=xbox`, свой app‑id) поверх
классического «терминального» зелёного вида. Тот вариант убран, а тема вплавлена
в `ui/src/styles.css` — палитра живёт в `:root`, структурные правила ниже, в
секции «Xbox appearance». Отдельного файла темы и плагина Vite больше нет: одна
таблица стилей вместо двух слоёв, и в бандл едет один набор объявлений.

Классический зелёный терминальный вид при этом исчез. Если он когда‑нибудь
понадобится обратно — это уже переключатель в настройках, то есть перевод темы
с этапа сборки на рантайм.

## Свой релей (нужно поднять до полноценной работы)

По умолчанию `DEFAULT_RELAY` пустой — клиент стартует и получает свой i2p‑адрес, но слать некуда, пока не указан релей.

> **Временный тестовый релей** в CI (workflow `relay-testnet`) **не работает
> с 2026‑07‑20**: репозиторий заархивирован, расписания не запускаются. Даже
> когда он бежал, он поднимался на go‑i2p, то есть по сети был недостижим.
> Сейчас он переведён на i2pd и оживёт, как только репозиторий разархивируют.
> Адрес печатается в Summary каждого запуска (артефакт `relay-destination`);
> вставлять его в Настройки → адрес релея. Только для тестов: ключ этого релея
> по определению не доверенный.

Разверни свой:

1. На сервере запусти i2pd (юнит `core/relay/gipny-i2pd.service`) — он поднимает SAMv3 на `127.0.0.1:7656`.
2. Запусти `gipny-relay` (юнит `core/relay/gipny-relay.service`, `GIPNY_RELAY_DATA=/var/lib/gipny-relay`). При первом старте он печатает `I2P DESTINATION: <base64>`.
3. Впиши это значение в `libcore/src/relay.rs::DEFAULT_RELAY` и пересобери. (Аналогично — сервер обновлений в `libcore/src/update.rs::DEFAULT_UPDATE_ONION`.)

Оба systemd‑юнита уже в `core/relay/` (релей зависит от юнита роутера через `Requires=`/`After=`). Пока адрес релея не зашит, клиент по дизайну молчит. Пересобирать при этом не обязательно: в **Настройках** приложения есть поле адреса релея — оно переопределяет вшитый `DEFAULT_RELAY`, так что destination своего релея можно просто вставить туда.

> `DEFAULT_RELAY` пустой не из‑за проблем с генерацией ключей — destination проверен: 391 байт, корректный KeyCertificate (Ed25519 + X25519), «повтор» в base64 это штатный i2p‑паддинг коротких ключей. Пусто просто потому, что боевой релей ещё не развёрнут; правильный адрес печатает сам `gipny-relay` при первом запуске.
>
> Пока релей не задан, клиент запускается и пускает внутрь, но вверху висит
> предупреждение и отправка недоступна. Раньше он в этом случае навсегда
> оставался на экране загрузки.

## Bot SDK — быстрый старт

```rust
use gipny_bot::{Bot, BotTarget};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    Bot::builder()
        .data_dir("./bot-data")
        .display_name("stats-bot")
        .on_command("export", |ctx, _arg| async move {
            let today = generate_today_report().await?;
            ctx.send_attachments_with_buttons(
                "stats ready",
                vec![("today.csv".into(), today)],
                vec![vec![("refresh".into(), "export".into())]],
            ).await?;
            Ok(())
        })
        .build()?
        .run().await
}
```

## Модель безопасности за 60 секунд

| Слой              | Что защищает                                                                 | Что всё ещё утекает                                                |
| ----------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Личность          | ed25519 + x25519 — ни телефона, ни email, ни логина; i2p‑адрес новый каждую сессию — по адресу сессии не связать | Публичный ключ — долгоживущий идентификатор: кто его знает, может соотнести адресованный тебе трафик на релее |
| Сеть              | i2p (входящие/исходящие туннели, чесночная маршрутизация)                    | i2p уязвим к статистическим атакам на уровне глобального наблюдателя |
| Сервер (релей)    | sealed sender — релей не видит отправителя; только `{получатель, блоб}`      | Один канонический релей = единая точка отказа доставки (не крипты)  |
| Контент           | X3DH + Double Ratchet + XChaCha20‑Poly1305 — полная forward secrecy         | Компрометация устройства с разблокированным хранилищем вскрывает текущую сессию |
| На диске          | SQLCipher (AES‑256) + Argon2id + duress‑пароль; **i2p‑ключ на диск не пишется вовсе** (адрес эфемерный), в памяти — в `Zeroizing` | Извлечение RAM методом cold‑boot теоретически возможно            |
| Размеры (метадата)| Паддинг по фиксированным корзинам (256 Б → 16 МиБ)                           | Выбор корзины всё же разбивает трафик на классы размеров           |

### Честные оговорки

- **Транспорт проверен ровно один раз.** i2pd — зрелый роутер, но связка
  «релей + два бота поверх live i2p» подтверждена одним прогоном e2e
  (5/5 сообщений, медиана 5.8 с). Ночной прогон с тех пор не выполнялся —
  репозиторий заархивирован.
- **Боевого релея нет.** `DEFAULT_RELAY` пустой; без адреса релея отправка
  недоступна. Это единственная точка отказа доставки (не крипты) и она сейчас
  не развёрнута.
- **Автообновление не работает.** Сервер обновлений не развёрнут, весь
  соответствующий UI скрыт.
- **Android не проверен.** i2pd собирается под Android и экспортирует нужные
  символы, но ни одна APK с ним ещё не запускалась на устройстве.
- Маленькая аудитория → меньше стороннего ревью, чем у Signal.
- Независимого крипто‑аудита пока нет. Крипто‑ядро (`libcore/src/crypto.rs`)
  вообще не покрыто тестами.
- Один канонический релей; мульти‑релей — в планах.
- Нет мультиустройства: одна личность = один активный клиент. Для миграции — экспорт/импорт, затем закрыть старый клиент.
- Первое i2p‑соединение медленнее, чем в Tor (reseed + построение туннелей).

Экран **«Безопасность и анонимность»** внутри приложения содержит полный разбор.

## Где лежит профиль / данные

```
Linux:    $XDG_DATA_HOME/gipny-i2p/profiles/<имя>/   (по умолчанию: ~/.local/share/gipny-i2p/...)
Windows:  %APPDATA%/gipny-i2p/profiles/<имя>/
macOS:    ~/Library/Application Support/gipny-i2p/profiles/<имя>/
Android:  /data/user/0/app.gipny.i2p/gipny/profiles/<имя>/
```

В каждом профиле — база SQLCipher, состояние i2p‑роутера (`i2p/`) и блобы `attachments/`. Ключа i2p‑адреса на диске нет: адрес эфемерный и живёт только в памяти сессии. Стереть профиль — удалить его каталог; duress/auto‑wipe затирает его рекурсивно с перезаписью.
