# tests/e2e-harness — сквозной тест доставки по живой i2p

Запускает два headless-клиента на общем роутере, связывает их, гоняет сообщения с вложением и эхом и печатает задержки. Это единственная проверка того, что сообщения реально доходят. Запускается только в CI (`.github/workflows/e2e-i2pd.yml`).

## Что здесь

| Файл | За что отвечает |
|---|---|
| `src/main.rs` | `main` выбирает сценарий по переменным окружения. `start_bot` — клиент на `SessionManager`. `start_in_process_relays` — два личных `EphemeralRelay` в процессе. `run_agent_mode` — сценарий с настоящим `gipny-agent`. `wait_for` и `compute_latencies` — ожидания и таймингы. Успех — строка `[e2e] SUCCESS`, тайминги — блок `[e2e-timing]` |
| `start-router.sh` | Поднимает общий i2pd с SAM на 7656 и ждёт туннелей. Вызывается из всех джоб e2e |

**Переменные окружения:**

- `E2E_RELAY_DEST`, `E2E_RELAY_DEST_A`, `E2E_RELAY_DEST_B` — адреса внешних релеев;
- `E2E_IN_PROCESS_RELAYS=1` — релеи внутри процесса;
- `E2E_AGENT_BIN` — путь к `gipny-agent`, включает режим агента;
- `E2E_N_MESSAGES` — число сообщений;
- `E2E_TIMEOUT_SECS` — таймаут;
- `E2E_WORK_DIR` — каталог состояния;
- `GIPNY_SAM_PORT` — порт SAM общего роутера.

## Сценарии в CI

| Джоба | Переменные | Что доказывает |
|---|---|---|
| `e2e (relay + two bots)` | `E2E_RELAY_DEST_A`/`_B` (два `gipny-relay`) | Письмо кладётся на релей **получателя**; по результату двигается пин i2pd |
| `e2e (relays inside the bots)` | `E2E_IN_PROCESS_RELAYS=1` | Встроенный релей `libcore` работает по живой i2p |
| `e2e (agent binary)` | `E2E_AGENT_BIN`, `E2E_IN_PROCESS_RELAYS=1` | Агент: GRANT, команды по очереди, загрузка файла, OFF → REVOKE |

## Куда вносить правки

| Задача | Где |
|---|---|
| Новый сценарий | ветка в `main` по новой переменной `E2E_*` + джоба в `e2e-i2pd.yml` |
| Число и содержимое сообщений, критерий успеха | `main` (для агента — `run_agent_mode`) |
| Запуск роутера, ожидание туннелей | `start-router.sh` |
| Отчёт по задержкам | `compute_latencies`, шаг `timing summary` в `e2e-i2pd.yml` |

## Инварианты и грабли

- **Харнесс работает на `SessionManager`, а не на `Core`.** Логику приложения (запросы в контакты, режимы релея в `Core`) он не проверяет.
- **Один роутер на всех:** на хосте только один роутер может держать I2CP. Отдельный роутер для каждого бота ломал прогоны.
- **Холодный роутер и туннели занимают минуты.** Один прогон длится около 10–15 минут при лимите джобы 30.
- **Мок-режима SAM нет, и это намеренно:** зелёный прогон на моке ничего не говорил.

## Как проверить

```
env -u CC -u CXX cargo check -p e2e-harness
```

Настоящий прогон — ручной запуск `e2e-i2pd` на нужной ветке со страницы Actions (из `gh` запуск возвращает 403). В логах смотреть `[e2e] SUCCESS`.
